1. **Risk — `session` PATH.** The prefix order and empty-`PATH` handling are sound, but the script must spell Bash’s expansion as `''${PATH:+:$PATH}` inside Nix’s indented string. The `writeShellApplication` wrapper reads `$PATH` before `session` runs; in this pinned Bash, an unset inherited `PATH` becomes `/no-such-path`, so the proposed “unset gives only base/bin” assertion is false. Inherited relative entries also change meaning after `cd -P`; a bare `exec "$@"` searches the resulting `PATH`, while an argv containing `/` runs relative to the clone. A separate `base` argument is better for the fixture seam. [design.md](/home/david/dev/oubliette/.doctrine/slice/007/design.md:74), [session.nix](/home/david/dev/oubliette/vm/session.nix:54).

2. **Disagree — collision guarantee.** `buildEnv` defaults to `ignoreCollisions = false`, but also to `checkCollisionContents = true`: equal-content, equal-mode files are accepted. Repeated store paths and symlinks resolving to the same target are skipped; differing priorities can select a file without failing. Its default `pathsToLink = [ "/" ]` does cover `bin`, including symlinked directories. Putting the base in `systemPackages` works, but NixOS’s outer system path ignores collisions, so the base’s check says nothing about conflicts with core packages. In particular, its `bash` and `coreutils` can change which binaries interactive users get. A store-path `jq` adds a direct runtime closure dependency as intended; it does not introduce an evident cross-compilation issue. Keep suite-owned `jq` where fixtures invoke it.
